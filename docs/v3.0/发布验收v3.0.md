# OpSense v3.0 发布验收

M37 将代码回归、合成样本评测和真实服务器证据分成三层。合成样本可以阻止算法和预算回退，但不能代替真实网络、SSH、发行版与权限条件下的 P95 数据。

## 仓库内验收

运行：

```bash
pnpm run check
pnpm run evaluate:v3
```

`evaluate:v3` 读取 `fixtures/evaluation/v3-release-samples.json`，覆盖以下场景标签：

- Debian/Ubuntu 与 300 个 systemd unit；
- RHEL/Rocky；
- Alpine/非 systemd；
- 100 个容器与 Compose；
- Go/Rust 自研进程和非标准路径；
- Docker 权限不足的最小权限账户。

合成门禁包括高价值 Candidate 召回率、系统对象误报率、未知服务比例、Probe 接受率、Inventory P50/P95、基础 SSH 命令数、AI 调用数与 token P50/P95。

## 单次运行基准

```bash
opsense benchmark --run <run-id>
opsense benchmark --compare <old-run-id> <new-run-id>
```

该命令直接读取 run 目录中的 `run.json` 与 `metrics.json`，报告 Inventory 墙钟时间、SSH 命令数、旧式 N+1 命令、候选/服务数、Probe 信息增益、AI 调用/token 和报告耗时。比较模式输出各指标增量。

## 真实服务器门禁

在不提交到 Git 的 `fixtures/evaluation/v3-real-server-samples.local.json` 中保存脱敏结果，然后运行：

```bash
pnpm run release:v3
```

文件格式与合成样本一致，但 `source` 必须为 `real`。真实样本整体必须覆盖这些 tag：

```text
debian-ubuntu
rhel-rocky
no-systemd
docker-compose
custom-service
minimal-permission
```

对象 ID 必须替换为不可逆的稳定别名；不得保存主机名、IP、用户名、配置值、凭据或业务数据。每次测量应记录 RTT，正式性能结论只使用 RTT 不高于 50 ms、systemd unit 少于 500、容器不超过 100 的标准样本。

真实样本未覆盖完整时，`release:v3` 会以非零状态退出。这是预期的发布阻断，不影响日常 `check` 和合成回归。

## 发布阈值

| 指标 | 门禁 |
| --- | ---: |
| 高价值 Candidate 召回率 | 100% |
| 普通系统对象误报率 | ≤ 5% |
| 未知服务比例 | ≤ 30% |
| Probe 接受率 | ≥ 50% |
| 首个 Inventory P50 | ≤ 30 秒 |
| 首个 Inventory P95 | ≤ 60 秒 |
| 基础 SSH 命令数 | ≤ 40 |
| 单次 Pipeline AI 调用 | ≤ 6 |
| token P50 | ≤ 30 万 |
| token P95 | ≤ 50 万 |

只有 `pnpm run check`、`pnpm run evaluate:v3` 和带完整真实样本的 `pnpm run release:v3` 全部通过，才能声明 v3.0 达到 Definition of Done。
